# 午点通 · 资阳校园集运交互 Demo v0.1

## 当前推荐：Stage 2 前后端版本

项目现已新增 `backend/`（FastAPI + SQLite）和 `frontend/`（React + TypeScript + Vite）。要检查真实后端持久化流程，请分别启动：

```powershell
# 终端一：项目根目录
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8001

# 终端二：项目根目录
Set-Location .\frontend
npm run dev
```

然后访问 `http://127.0.0.1:5173`。详细说明见 `backend/README.md` 和 `frontend/README.md`。

Stage 4 已提供一键方式：首次安装完成后，直接双击 `start_demo.bat`；重置使用 `reset_demo.bat`；完整说明见 `README_运行手册.md`。

下方“30 秒启动”保留的是原静态原型说明；它不连接后端，仅用于回归对照。

> **这是纯本地、可交互的业务演示原型**，并非已上线的 SaaS 或可用于真实交易的平台。
> 所有商家名称、菜单、订单、收费与时间均为**虚构测试数据**。学校及入校地点尚未获得确认。没有真实支付、资金结算、学生隐私数据或服务器。

## 30 秒启动

1. 解压 ZIP 到电脑上的一个文件夹。
2. 双击其中的 `index.html`，用 Chrome / Edge 打开。
3. 左侧导航切换「学生」「商家」「城区司机」「校园交付」「运营总览」「异常与成本」。
4. 随时可以点击页面右上角「重置演示」恢复30笔模拟订单。

如果双击后受浏览器本地文件限制，可在该文件夹启动终端：

```powershell
python -m http.server 8000
```

然后浏览器打开 `http://localhost:8000`。不需要安装 Node、数据库或任何第三方依赖。

## 建议按这个顺序演示完整业务流程

1. **学生端**：选择梅西或达高的模拟商户，添加商品，选择模拟交付点，提交订单。
2. **运营总览**：确认10:40截单。已截单不能向本班新增订单。
3. **商家端**：依次切换3家商户，每家点击「确认本班订单」及「全部模拟打包」。
4. **司机端**：按取货线路顺序 A店→B店→C店操作。第三家可选择「模拟缺1袋并交接」，观察系统生成异常订单。确认发车。
5. **校园端**：模拟到校清点、分配配送任务和完成交付。
6. **异常与成本**：对缺袋异常做**模拟退款**，查看班次是否结案，调整固定运输成本，观察班次贡献。

## 你正在看到的能力

- 单校区、单午餐班次、固定截单和发车时间
- 3家虚拟商户（梅西商圈2家、达高商圈1家）、30笔预置订单、34个餐袋
- 订单和餐袋分别追踪；司机未取到的餐袋不会因为发车而变成运输中
- 商家批量接单打包，司机逐店核对，到校集中交接
- 演示少取一袋、异常留痕、模拟退款、成本模型
- 浏览器 localStorage 本机暂存，刷新页面仍保留；重置后恢复初始数据

## 局限性：不要把这个原型误当成正式平台

- 目前只有浏览器本地数据，没有后端、数据库或多人实时同步；换台电脑数据不共享
- 左侧角色切换仅用于演示，不具备真实身份认证或权限隔离
- 目前为班次/商家级批量确认；正式履约系统还需逐单逐袋核对、可追溯扫码与交付凭证
- 目前没有真实支付、退款、商家分账、资质核验、商户正式入驻、通知推送
- 固定时间、校园交付地点、司机取货线路尚未经真实测试或校方许可
- 成本模型只按假设数计算，不能直接作为投资测算

## 如何让 Codex 接手

打开整个文件夹作为 Codex 工作区，把 `PRD_资阳校园集运Demo_v0.1.md` 和 `Codex_开发启动指令.md` 提供给它。

**要求 Codex 在此原型上继续开发有后端的正式 Demo**，而不是仅根据截图重做一个样板商城。优先保留已有业务引擎规则和演示路径，并使其通过后端接口执行和持久化。
